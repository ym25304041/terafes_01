### A-6. URLパラメータの扱い【追加】

画面は、URLのパラメータを検査してから使う。不正な値は、エラーにせず**既定値に置き換える**。

| 画面 | パラメータ | 受け付ける値 | 不正なとき |
| :--- | :--- | :--- | :--- |
| ゲームプレイ | `stage` | 1〜9999の整数 | ステージ1として扱う |
| ゲームプレイ | `retry` | 0 または 1 | 0として扱う |
| 結果（クリア・失敗） | `stage` | 1〜9999の整数 | 1 |
| 結果（クリア） | `steps` | 0〜100の整数 | 0 |
| 結果（失敗） | `reason` | 失敗理由の5種類（A-4-5） | `NOT_REACHED_GOAL` |

- `stage` が範囲内の整数でも、ステージファイルが無いときは、ゲームプレイ画面の読み込み失敗（FR-PLY-26）になる（ステージ1にはならない）。
- 数字以外の文字・7桁以上の数字は、不正として扱う。

## 3. ルール仕様の補足案（境界値・同時に起きること）【追加】

### B-1. 最大ステップ数（100回）の境界

| ID | 内容 |
| :--- | :--- |
| RL-STEP-01 | 100回目の行動でゴールに着いたときは、クリア（実行回数 100）。 |
| RL-STEP-02 | 100回行動したあと、**まだ行動するブロックが残っている**ときは、101回目の行動をしようとした時点で停止し、`STEP_LIMIT_EXCEEDED`（失敗）。このとき実行回数は 100 のままで、101回目は実行しない。 |
| RL-STEP-03 | 100回行動して、実行するブロックがそれ以上無く、ゴールに着いていないときは、`NOT_REACHED_GOAL`。 |
| RL-STEP-04 | 上限による停止は、テスト実行でも失敗として扱い、理由を表示する。 |

### B-2. 最大処理回数（1000回）の数え方【要確認】

現在の実装は、次の合計が **1000回を超えた**時点で停止する（`LOOP_LIMIT_EXCEEDED`）。

- ブロック1つの実行（入れ子の中のブロックも、実行するたびに数える）
- 「…の間」「回くり返す」の1周ごと

条件の評価そのものは数えていない。仕様書の「条件の評価」の文言を、実装に合わせて直すか、実装を直すかを決める（推奨: 文言を実装に合わせる）。1000回ちょうどは停止せず、1001回目で停止する。

### B-3. 入れ子の深さ・ブロック数の数え方

| ID | 内容 |
| :--- | :--- |
| RL-NEST-01 | 制御ブロック（もし・の間・回くり返す）は、**6段まで**重ねられる。7段目の制御ブロックを含むプログラムは `PROGRAM_TOO_DEEP`（400）で拒否する。6段目の制御ブロックの中には、制御ブロックでないブロック（向く・移動など）だけ置ける。 |
| RL-NEST-02 | ブロック数は、入れ子の中も含めて**200個まで**。201個以上は `PROGRAM_TOO_LONG`（400）。 |

### B-4. 同時に起きること・状態の補足

| ID | 内容 |
| :--- | :--- |
| RL-OVER-01 | クリアまたは失敗が決まった時点で、残りのブロックは実行しない。敵も動かない。 |
| RL-ENEMY-01 | 同じマスに敵が複数いて武器を持っているとき、そのマスの敵を**すべて**討伐する。 |
| RL-ENEMY-02 | アリが先に行動する。アリが動いた先に、敵が（動く前から）いれば、戦闘になる。アリと巡回する敵が、同じ1ステップで互いのマスへ入れ替わる場合も、アリが先に動くため、アリが入ったマスに敵がまだいれば戦闘になる。 |
| RL-ENEMY-03 | 敵が動いて、待っているアリのマスに入ってきたときも、戦闘になる。武器があれば討伐、無ければ敗北。 |
| RL-COND-01 | `目の前に壁がある` は、マップの外も壁として扱う。閉じたドアは壁として扱わない。 |
| RL-COND-02 | `目の前に落とし穴がある` は、マップの外では成り立たない（偽）。 |
| RL-COND-03 | `目の前に敵が来る` は、目の前のマスに敵が**今いる**、または**次のステップで入ってくる**とき成り立つ。 |
| RL-ITEM-01 | ジャンプの着地点にアイテム・敵・スイッチがあるときも、移動で着いたときと同じ自動処理を行う（落下→取得→戦闘→スイッチ→ゴール）。 |
| RL-ITEM-02 | 「アイテムを捨てる」は、アリが立っているマスにだけ置ける。捨てたアイテムは、床のアイテムと同じに扱う。 |
| RL-TEST-01 | テスト実行は、ゴールに着いてもクリアにならない。ゴール以後も、プログラムを最後まで実行する。 |

## 4. API仕様の追記案（新章 2.4 として）【追加】

詳細な仕様は `ant-game/README.md` の「API」にある。仕様書には、テストの根拠になる要点を載せる。

| ID | API | 内容 |
| :--- | :--- | :--- |
| FR-API-01 | `GET api/stages` | ステージの一覧（番号・名前・説明）を、番号の小さい順に返す。ステージファイルの誤りがあるときは `500 STAGE_DATA_ERROR`。 |
| FR-API-02 | `GET api/stage?id=N` | マップ（5行）・開始位置・最初の向き・敵の初期位置を返す。`id` が数値でないときは `400 INVALID_STAGE_ID`、ファイルが無いときは `404 STAGE_NOT_FOUND`。 |
| FR-API-03 | `POST api/run` | プログラムを最後まで実行し、結果（`status`、`failReason`、`stepCount`、1ステップごとの `trace`）を返す。クリアも失敗も `200`。 |

`POST api/run` の入力検証:

| 検査 | 条件 | エラー |
| :--- | :--- | :--- |
| Content-Type | `application/json` で始まること | `415 UNSUPPORTED_MEDIA_TYPE` |
| 本文の大きさ | 64KB（65,536文字）以下 | `413 REQUEST_TOO_LARGE` |
| JSON | 正しい形式 | `400 INVALID_JSON` |
| 最上位 | オブジェクト | `400 INVALID_REQUEST` |
| `stageId` | 1〜10000の整数 | `400 INVALID_STAGE_ID` |
| `program` | 配列 | `400 INVALID_PROGRAM` |
| `testRun` | 省略可。真偽値のみ | `400 INVALID_REQUEST` |
| ブロック | 種類・方向・条件・回数（1〜100）が許可した値 | `400 INVALID_BLOCK` |
| ブロックのID | 英数字・`-`・`_` の1〜32文字 | `400 INVALID_BLOCK_ID` |
| 入れ子 | 制御ブロックは6段まで | `400 PROGRAM_TOO_DEEP` |
| ブロック数 | 200個まで | `400 PROGRAM_TOO_LONG` |
| ステージ | ステージファイルがある | `404 STAGE_NOT_FOUND`（誤りがあれば `500 STAGE_DATA_ERROR`） |
