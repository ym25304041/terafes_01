## 1. 概要
本仕様書は、PCブラウザ（Chrome）上で動作する未経験者向けプログラミング学習ゲームの機能要件および非機能要件を定義したドキュメントである。
プレイヤーはドラッグ＆ドロップ形式でコーディングブロックを組み立て、アリ型ロボットの行動をプログラミングしてステージクリアを目指す。

製品名は『Aligorithm』とする。ブラウザのタブの名前とTOP画面の文字タイトルも「Aligorithm」と表示する。

---

## 2. 機能要件 (Functional Requirements)

### 2.1. 画面構成および画面遷移要件
画面遷移順序は以下の通りとする。
`TOP画面` ➔ `ステージ選択画面` ➔ `ゲームプレイ画面` ➔ `リザルト画面（クリア／失敗）`
また、ステージ選択画面からは `ルール説明画面` へ遷移でき、ルール説明画面からステージ選択画面へ戻れる。

画面のファイルは、`index.html`（TOP）、`stages.html`（ステージ選択）、`game.html`（ゲームプレイ）、`result-clear.html`（リザルト・クリア）、`result-fail.html`（リザルト・失敗）、`rule.html`（ルール説明）とする。画面の背景・マップの各マス・アリロボット・敵・アイテム・タイトルロゴ・リザルトの画像は、画像ファイルの差し替えで変更できる（差し替え方法は `ant-game/README.md` の「画像素材」を参照）。

#### (1) TOP画面
* **配置要素:**
  * 画面中央上部: ゲームタイトルのテキストを表示。
  * 画面中央下部: 「ゲーム開始」ボタンを設置。
* **動作仕様:**
  * 「ゲーム開始」ボタンをクリックすると、ステージ選択画面へ遷移する。
  * `FR-TOP-01` タイトルロゴ画像（`assets/` 配下）が読み込めたときは画像、無いときは文字のタイトルを表示する。
  * `FR-TOP-02` 「▶ ゲーム開始」を押すと `stages.html` へ遷移する。
  * `FR-TOP-03` この画面を開いた時点で、失敗後のやり直し用に預かっているプログラム（sessionStorage）を破棄する。

#### (2) ステージ選択画面
（ステージは9つ表示する。ステージファイルがまだないステージは、押せない「じゅんびちゅう」の表示にする。）
* **配置要素:**
  * 画面上部: 「⌂ ホーム」ボタン（TOP画面へ）、「📖 ルール説明」ボタン（ルール説明画面へ）。
  * 画面メイン領域: 整然と並んだ四角いブロック形式のステージ選択ボタンを配置。
  * ゲームルールの説明は、ステージ選択画面には掲載せず、「ルール説明」ボタンの先の画面（ルール説明画面）に掲載する。
* **動作仕様:**
  * 選択されたステージのゲームプレイ画面へ遷移する。
  * `FR-STG-01` ステージは9枠を表示する。ステージファイルがある枠は、番号・ステージ名・説明文のカードを表示し、押すと `game.html?stage=N` へ遷移する。
  * `FR-STG-02` ステージファイルが無い枠は、「じゅんびちゅう」と表示する押せないカードにする。
  * `FR-STG-03` ステージ一覧を取得できなかったときは、「ステージの一覧を読み込めませんでした。」とエラーの文言を表示する。
  * `FR-STG-04` 「⌂ ホーム」で `index.html` へ、「📖 ルール説明」で `rule.html` へ遷移する。
  * `FR-STG-05` この画面を開いた時点で、預かっているプログラムを破棄する。

#### (3) ゲームプレイ画面
* **配置要素:**
  * **ステージ描画エリア:** 画面全体が見えるサイコロ状のマス目（グリッド）で区切られた2Dマップ。
  * **コーディングエリア:** アリを操作するためのプログラムブロックをドラッグ＆ドロップで配置・組み立てる領域。
  * **操作ボタン群:**
    * 「テスト実行」ボタン（「実行」ボタンの左に置く。表示は「▷ テスト実行」）
    * 「実行」ボタン（表示は「▶ 実行」）
    * 「プログラムのクリア」ボタン（プログラムのブロックをすべて消す。「プログラム」の見出しの右端に置く。表示は「クリア」）
    * ※「やり直す」「ステージ選択に戻る」ボタンは置かない。ステージ選択へは、画面左上のメニュー（☰）から戻る。
* **動作仕様:**
  * ステージ開始時にクリア目標を表示する。具体的には、ステージ番号・ステージ名・説明文を表示する（説明文が無いときは「アリロボットを動かして、ゴールを目指そう。」を表示する）。クリア目標のタイプ（2.3(2)）は、画面には表示しない。
  * ブロックをドラッグ＆ドロップでコーディングエリアに配置・編集できる。
  * 「実行」ボタン押下時、プログラムに従ってアリが自動行動を開始する。
  * アリが動作している間、現在実行されているブロックを強調（ハイライト）表示する。
  * 失敗時（途中でゲームオーバーになった場合、ゴールに着けなかった場合、または実行回数・処理回数の上限を超えて強制停止した場合）は、その場で動作が停止し、リザルト画面（失敗）へ遷移する。失敗の理由を表示し、「もう一度挑戦する」で同じステージのゲームプレイ画面へ戻れる。このとき、**失敗した時点のプログラム（ブロック）は、結果画面（失敗）で「もう一度挑戦する」が押されるまで保持し、押されたらそのまま復元して再開できる**（組み直さずに、直して再挑戦できる）。保持したプログラムは、再開した時点、またはタイトル・ステージ選択・結果画面（クリア）が開かれた時点で破棄する。
  * クリア条件を満たした場合、リザルト画面（クリア）へ遷移する。クリアまでにかかった実行回数（ステップ数）を表示する。
  * 「テスト実行」ボタンを押すと、プログラムの動きを再生するだけで、**ゴールの判定（クリア・失敗の判定）を行わない**。ゴールに着いてもクリアにならず、プログラムを最後まで実行し、結果画面へは遷移しない。再生が終わってから3秒後に、マップをステージの最初の状態に戻す（組んだプログラムは残る）。落とし穴への落下、敵への敗北、実行上限（50ステップ・1000回）で止まる場合は、その理由を表示して止まる。再生中は、「実行」「テスト実行」ボタンは押せない。
  * 「プログラムのクリア」ボタンを押すと、プログラムのブロックがすべて消える（再生中は押せない）。
  * ブロックは、パレットからプログラムへドラッグ＆ドロップで配置できる（クリックでも追加できる）。プログラム内のブロックは、ドラッグで並べ替え・別の枠への移動ができ、×ボタンで削除できる。
  * マップは、縦5×横9のマスを、上から見下ろした形で、隙間なく並べて表示する。

##### (3-2) ブロックの名称・設定項目・初期値
| 種類 | 仕様書での名称 | 画面の表示 | 設定項目（初期値） | 内部コード |
| :--- | :--- | :--- | :--- | :--- |
| 向く | 向く（上・下・左・右） | 「[方向]を向く」 | 方向: ↑上・↓下・←左・→右（初期: 右） | `TURN` |
| 移動 | 移動 | 「前へ移動」 | なし | `MOVE` |
| ジャンプ | ジャンプする | 「前へジャンプ」 | なし | `JUMP` |
| 待つ | 待つ | 「待つ」 | なし | `WAIT` |
| 捨てる | アイテムを捨てる | 「アイテムを捨てる」 | なし | `DROP` |
| 移動関数 | 移動関数 | 「移動関数([方向][回数]回)」 | 方向（初期: 右）、回数 1〜100（初期: 3） | `MOVE_FUNCTION` |
| もし | もし(条件)なら…そうでなければ | 「もし[条件]なら」。枠「なら」「そうでなければ」 | 条件（初期: 目の前に壁がある） | `IF` |

##### (3-3) ブロックの編集操作
| ID | 内容 |
| :--- | :--- |
| `FR-PLY-10` | パレットのブロックを、プログラム欄へドラッグ＆ドロップすると追加される（パレット側のブロックは減らない）。ドロップ先は、ブロックの上（そのブロックの前に入る）、制御ブロックの枠の中、プログラムの最後の領域。 |
| `FR-PLY-11` | パレットのブロックをクリックすると、「追加先に選んでいる枠」の最後に追加される。追加先の初期値は「プログラムの最後」。制御ブロックの枠の見出し（「▼ なら(ここに追加)」など）をクリックすると、その枠が追加先になり、強調表示される。 |
| `FR-PLY-12` | プログラム内のブロックは、ドラッグで並べ替え・別の枠への移動ができる。同じ配列内で前から後ろへ移動しても、置き先がずれない。 |
| `FR-PLY-13` | ブロックを、そのブロック自身の内側（入れ子の中を含む）へ移動することはできない（何も起きない）。 |
| `FR-PLY-14` | ブロックの×ボタンで、そのブロックを消せる。制御ブロックを消すと、中のブロックも消える。追加先に選んでいた枠が消えたときは、追加先が「プログラムの最後」に戻る。 |
| `FR-PLY-15` | 回数の入力欄（移動関数・回くり返す）は、1〜100の整数に丸める。0以下は1、101以上は100、数字でない入力は1、小数は小数点以下を切り捨てる。 |
| `FR-PLY-16` | 「クリア」ボタンで、プログラムのブロックがすべて消え、追加先が「プログラムの最後」に戻る。メッセージ欄に「プログラムを空にしたよ。」と出る。 |
| `FR-PLY-17` | **再生中**は、ブロックの追加・移動・削除・追加先の選択・クリアのどれも受け付けない。ブロックの設定欄（方向・条件・回数）も、再生中は変更できない。 |
| `FR-PLY-18` | 入れ子の深さ（制御ブロックは6段まで）とブロック数（合計200個まで）の上限は、画面では制限しない。上限を超えたプログラムを実行すると、サーバーが拒否し、メッセージ欄にエラーが出る（(3-5)）。 |

##### (3-4) 実行・再生
| ID | 内容 |
| :--- | :--- |
| `FR-PLY-20` | プログラムが空のとき、「実行」「テスト実行」を押しても何も実行せず、「ブロックを置いてから、実行してね。」と出す。 |
| `FR-PLY-21` | 実行を始めると、マップ・アリ・敵・もちものを最初の状態に戻してから、サーバーの結果を再生する。再生中は「実行」「テスト実行」が押せない。 |
| `FR-PLY-22` | 再生は、1ステップごとにアリと敵を動かし、実行中のブロックを強調表示する。条件を調べたブロックは、成り立てば緑、成り立たなければ赤で示す。1ステップの長さは **420ミリ秒**。 |
| `FR-PLY-23` | 【実行】再生が終わったら、クリアなら「ゴール！」、失敗なら「…」を表示して**800ミリ秒**待ち、結果画面へ遷移する。失敗のときは、遷移の前に、失敗した時点のプログラムを sessionStorage に預ける。 |
| `FR-PLY-24` | 【テスト実行】再生が終わっても結果画面へ遷移しない。メッセージ欄に「テスト実行が終わったよ。」と、落下・敗北・上限超過で止まったときはその理由、「(3秒後に最初の状態に戻るよ)」を出す。3秒後にマップを最初の状態に戻し、「最初の状態に戻したよ。」と出して、ボタンを押せる状態に戻す。組んだプログラムは残る。 |
| `FR-PLY-25` | 実行が通信エラーやサーバーのエラーで失敗したときは、エラーの文言をメッセージ欄に出し、ボタンを押せる状態に戻す。結果画面へは遷移しない。 |
| `FR-PLY-26` | ステージを読み込めなかったとき（存在しない、ステージファイルの誤り、通信エラー）は、ミッション欄に「ステージを読み込めませんでした」、メッセージ欄にエラーの文言を出し、「実行」「テスト実行」を押せなくする。 |
| `FR-PLY-27` | 「もう一度挑戦する」から来た場合（`retry=1`）で、預かっていたプログラムが同じステージのものなら、復元して「前回のプログラムをそのまま残したよ。直して、もう一度挑戦しよう!」と出す。復元するとき、知らない種類のブロックは捨て、方向・条件・回数は許可した値だけにし、ブロックのIDは振り直す。預かっているプログラムは、この画面を開いた時点で必ず破棄する。 |

#### (4) リザルト画面
* **配置要素（クリア）:**
  * 画面上部: 「ステージクリア」の画像（無いときは文字「ステージクリア！」）と、クリアまでにかかったプログラムの実行回数「ステージ N　実行回数: M 回」を表示。
  * 画面下部左側: 「ステージ選択へ戻る」ボタン（ステージ選択画面へ戻る）。
  * 画面下部右側: 「次のステージへ」ボタン（次のステージのゲームプレイ画面へ進む）。次のステージのファイルが無いときは、ボタンの表示が「ステージ選択へ」になり、ステージ選択画面へ遷移する。
* **配置要素（失敗）:**
  * 「ステージ失敗」の画像（無いときは文字「ステージ失敗…」）と、失敗の理由の文言（(3-5) の表）を表示。
  * 「もう一度挑戦する」ボタン（同じステージのゲームプレイ画面へ。失敗した時点のプログラムを復元する）、「ステージ選択へ戻る」ボタン（ステージ選択画面へ戻る）。
* **動作仕様:**
  * `FR-RES-01` （クリア）「ステージクリア」の画像（無いときは文字）と、「ステージ N　実行回数: M 回」を表示する。
  * `FR-RES-02` （クリア）「ステージ選択へ戻る」で `stages.html` へ。「次のステージへ」で次のステージ（N+1）のゲームプレイ画面へ。N+1 のステージファイルが無いときは、ボタンの表示が「ステージ選択へ」になり、`stages.html` へ遷移する。
  * `FR-RES-03` （クリア）開いた時点で、預かっているプログラムを破棄する。
  * `FR-RES-04` （失敗）「ステージ失敗」の画像（無いときは文字）と、失敗理由の文言を表示する。
  * `FR-RES-05` （失敗）「もう一度挑戦する」で `game.html?stage=N&retry=1` へ（プログラムを復元して再開）。「ステージ選択へ戻る」で `stages.html` へ。

#### (5) ルール説明画面
* `FR-RUL-01` `rule.html` に、ゲームルールの説明（7項目）を表示する。
* `FR-RUL-02` 「← 戻る」で `stages.html` へ戻る。

#### (6) URLパラメータの扱い
画面は、URLのパラメータを検査してから使う。不正な値は、エラーにせず**既定値に置き換える**。

| 画面 | パラメータ | 受け付ける値 | 不正なとき |
| :--- | :--- | :--- | :--- |
| ゲームプレイ | `stage` | 1〜9999の整数 | ステージ1として扱う |
| ゲームプレイ | `retry` | 0 または 1 | 0として扱う |
| 結果（クリア・失敗） | `stage` | 1〜9999の整数 | 1 |
| 結果（クリア） | `steps` | 0〜50の整数 | 0 |
| 結果（失敗） | `reason` | 失敗理由の5種類（(3-5)） | `NOT_REACHED_GOAL` |

* `stage` が範囲内の整数でも、ステージファイルが無いときは、ゲームプレイ画面の読み込み失敗（`FR-PLY-26`）になる（ステージ1にはならない）。
* 数字以外の文字・7桁以上の数字は、不正として扱う。

#### (7) エラー画面・エラー応答
| ID | 内容 |
| :--- | :--- |
| `FR-ERR-01` | アプリに届いたリクエストが 400・404・405・500 のエラーになったとき（API が自分で返すエラーを除く）は、Tomcat の標準のエラーページ（バージョンや例外の詳細が出る）の代わりに、アプリのエラー応答を返す。ステータスコードは元のままにする。予期しない例外も、500 として同じ扱いにする。 |

| `FR-ERR-03` | API のリクエスト（`/api/` 配下）のときは、`{"error":"コード"}` の JSON を返す。コードは、400 → `BAD_REQUEST`、404 → `NOT_FOUND`、405 → `METHOD_NOT_ALLOWED`、それ以外 → `INTERNAL_ERROR`。 |

### 2.2. プログラミング（コーディング）仕様要件

#### (1) 基本仕様
* **ブロック配置:** 基本動作を記述したブロックを上から順に実行順序に従ってドラッグ＆ドロップで配置する。
* **ネスト（構造化）仕様:** 特殊処理ブロックは内部に他のブロックや枠を配置可能な「覆う枠」として機能し、条件と動作を設定できる。
* **最大ステップ数制限:** 1つのプログラムで実行できる処理（アリの行動＝向く・移動・ジャンプ・待つ・アイテムを捨てる）の上限は最大50回までとし、超えた場合は安全のため停止する。
* **最大処理回数制限:** アリが行動しないまま回り続けるプログラム（中身が空のくり返しなど）を止めるため、ブロックの実行回数とくり返しの周回数の合計が1000回を超えた場合も停止する。数え方は、ブロック1つを実行するたび、および「…の間」「回くり返す」が1周するたびに1回とする。条件の評価そのものは数えない。
* **アリの向き:** アリは上・下・左・右のいずれかを向いている。最初の向きはステージごとに決まる（指定がなければ右向き）。「移動」「ジャンプ」は、アリが**今向いている方向**へ進む。向きを変えるには「向く」ブロックを使う。向きは画面上でアリのマスに矢印で表示する。
* **時間（ターン）の考え方:** アリが1回行動する（向く・移動・ジャンプ・待つ・アイテムを捨てる）ごとに時間が1ステップ進む。壁にぶつかって動けなかった場合やジャンプに失敗した場合も1ステップ進む。1ステップの順番は「アリが先に行動 → そのあと敵が動く」とする。条件の評価だけでは時間は進まない。
* **入れ子の制限:** 制御ブロックの入れ子は6段まで、ブロックの合計数は200個までとする。

#### (2) 基本動作ブロック一覧
| ID | ブロック名 | 動作仕様 |
| :--- | :--- | :--- |
| `BLK-01` | **向く（上・下・左・右）** | その場で、指定した方向を向く。アリは動かないが、時間は1ステップ進み、敵は動く。 |
| `BLK-02` | **移動** | アリが今向いている方向へ1マス移動する。※壁・マップ外・閉じたドアには移動できず、その場にとどまる（1ステップとして数える）。敵のいるマスへ移動した場合は戦闘になる（2.2.(5)を参照）。 |
| `BLK-03` | **アイテムを捨てる** | 持っているアイテムを、今いるマスに置く。アリは動かないが、時間は1ステップ進み、敵は動く。何も持っていないとき、または今いるマスにすでにアイテムがあるときは、捨てられない（何も起きないが1ステップは進む）。捨てたアイテムは、そのマスに再び着いたときに、自動で拾える（その場に立ったままでは拾わない）。 |
| `BLK-04` | **待つ** | その場で1ステップ待つ。アリは動かないが時間は進み、敵は動く。 |
| `BLK-05` | **ジャンプする** | アリが今向いている方向へジャンプする。前方1マスが落とし穴のときだけ成功し、その1つ先のマスへ着地する。前方が落とし穴でない場合、または着地点が壁・閉じたドア・マップ外の場合は失敗し、その場にとどまる（1ステップとして数える）。着地点が落とし穴の場合は落下して失敗となる。 |

※アイテムの取得・スイッチの作動・敵との戦闘は、ブロックを使わず**自動で**行われる（2.2.(5)を参照）。「物を拾う」「攻撃する」ブロックは存在しない。アイテムを手放すときだけ、「アイテムを捨てる」ブロックを使う。

※画面上のブロックの表示名は、2.1(3) の (3-2) の表を参照（例: 「移動」は画面では「前へ移動」、「ジャンプする」は「前へジャンプ」）。

#### (2-2) 関数
関数は、複数のコマンドをまとめた、パラメータ付きのブロックである。コマンドと同じように、プログラムの中に置いて使える。コマンドとは別の種類のブロックとして扱う。
| ID | 関数名 | パラメータ | 動作仕様 |
| :--- | :--- | :--- | :--- |
| `BLK-06` | **移動関数** | 方向（上・下・左・右）、移動回数（1〜100） | 指定した方向を向き、その向きに、指定した回数だけ移動する。「向く」ブロックと「移動」ブロックを並べたのと同じ動作で、合計（回数+1）ステップかかる。 |

* 移動の途中で壁・マップ外・閉じたドアにぶつかって動けなくても、残りの移動を続ける（動けなかった移動も1ステップに数える）。
* 移動の途中でクリア・失敗（落下・敗北）が決まった場合は、そこで止まる。
* 今後、関数の種類を増やせる構造とする。

#### (3) 特殊処理（制御）ブロック一覧
制御ブロックは、内部に他のブロックを入れられる枠として機能する。制御ブロックの実行自体では、時間（ステップ）は進まない。
* `BLK-07` `もし(条件)なら(動作)する`（「そうでなければ(動作)する」の枠も持つ。省略した場合は何もしない）
* `BLK-08` `(条件)の間(動作)し続ける`（毎回、先に条件を調べる。条件が成り立たなくなったら抜ける）
* `BLK-09` `(数値)回実行する`（回数は1〜100）

条件には、「〜でない」を指定して、成り立つ・成り立たないを反転できる（例: 目の前に壁がない間、進み続ける）。

#### (4) 条件式一覧
* `CND-01` `目の前に壁があったら`
* `CND-02` `目の前に敵が居たら`
* `CND-03` `目の前に落とし穴があったら`
* `CND-04` `目の前に敵が来るなら`

「目の前」とは、アリが今向いている方向の1マス先を指す。
* `目の前に壁があったら`: 目の前が壁、またはマップの外（マップの端は壁として扱う）。閉じたドアは壁として扱わない。
* `目の前に敵が居たら`: 目の前のマスに、今、敵がいる（動かない敵・巡回する敵のどちらも）。
* `目の前に落とし穴があったら`: 目の前が落とし穴。マップの外では成り立たない（偽）。
* `目の前に敵が来るなら`: 敵が目の前のマスに、今いる、または次のステップで入ってくる。「安全に進めるか」の確認に使う。

| 条件 | 画面の表示（成り立つとき ／ 「〜でない」のとき） | 内部コード |
| :--- | :--- | :--- |
| 壁 | 目の前に壁がある ／ 目の前に壁がない | `WALL_AHEAD` |
| 敵 | 目の前に敵がいる ／ 目の前に敵がいない | `ENEMY_AHEAD` |
| 落とし穴 | 目の前に落とし穴がある ／ 目の前に落とし穴がない | `PIT_AHEAD` |
| 敵の接近 | 目の前に敵が来る ／ 目の前に敵が来ない | `ENEMY_COMING` |

※「進んだ位置に物が落ちていたら」「進んだ位置に物を置ける場所があったら」は、アイテムの取得・消費を自動化したため廃止した。

#### (5) アイテム・スイッチ・ドアの自動処理
アリがマスに着いた（移動またはジャンプの着地）時点で、次の処理が自動的に行われる。実行順序は「落とし穴の判定 → アイテム取得 → 敵との戦闘 → スイッチ作動 → ゴール判定」とする。ジャンプの着地点にアイテム・敵・スイッチがあるときも、移動で着いたときと同じ処理を行う（`RL-ITEM-01`）。

* **アイテム取得:**（`ITM-01`）
  * アイテムのあるマスにアリが着くと、自動で取得する。取得したアイテムはそのマスからなくなる。
  * アイテムは「物資」と「武器」の2種類で、アリが持てるのは**1つだけ**（スロットは1つ。物資か武器のどちらか）。
  * すでに何かを持っている場合は、アイテムのあるマスに着いても取得せず、アイテムはそのマスに残る。持ち替えるときは、先に「アイテムを捨てる」で手放す。
  * 持っているアイテムは、ゲームプレイ画面の「もちもの」枠に表示する。
* **スイッチ作動:**（`ITM-02`）
  * スイッチのマスにアリが着いたとき、物資を持っていれば、物資を1つ消費してスイッチが作動し、**同じ記号のドアがすべて開く**。
  * 物資を持っていない場合は何も起きない（スイッチのマスは通行できる）。後で物資を取得してから戻れば作動できる。
  * 作動したスイッチは再度乗っても物資を消費しない。ドアは一度開くと開いたままとなる。
* **武器:**（`ITM-03`）敵との戦闘判定に用いる。「持っているかどうか」のみを管理し、種類や強さはない。武器を持っていない状態（物資を持っている場合も含む）で敵と遭遇すると敗北する。
* **アイテムを捨てる:**（`RL-ITEM-02`）アリが立っているマスにだけ置ける。捨てたアイテムは、床のアイテムと同じに扱う。
* **敵との戦闘:**（`ENM-01`）
  * 敵は「動かない敵」と「巡回する敵」の2種類で、どちらも道のマス（巡回する敵は接敵ゾーン）の上にいる。
  * アリと敵が同じマスになった時点で、自動的に戦闘となる。次の2つの場合がある。
    * アリが敵のいるマスに着いた（移動またはジャンプの着地。アリの行動中）
    * 巡回する敵が動いて、アリのいるマスに入ってきた（敵の行動中。アリがその場で待っていても起きる）
  * **武器を持っている場合:** 敵を討伐し、そのマスに進める。討伐した敵はマップからいなくなる。武器は消費されないため、同じ武器で何体でも討伐できる。同じマスに敵が複数いるときは、そのマスの敵をすべて討伐する（`RL-ENEMY-01`）。
  * **武器を持っていない場合:** 敗北し、ゲームオーバーとなる。物資だけを持っていても討伐はできない。
  * 実行順序は「落とし穴の判定 → アイテム取得 → 敵との戦闘 → スイッチ作動 → ゴール判定」とする。
* **巡回する敵（接敵ゾーン）:**（`ENM-02`）
  * 敵は、決められた範囲（接敵ゾーン）を**縦1列、または横1列の直線上だけ**で往復する。複雑な動きはしない。
  * アリの行動のあと、敵は1ステップにつき1マス進む。範囲の端に着いたら、すぐに折り返す（端で止まらない）。
  * 敵は、ゾーンの左端（縦のゾーンは上端）から、反対側の端へ向かって動き始める。
  * アリが先に行動し、そのあとで敵が動く。アリの行動でクリア・失敗が決まった場合、敵は動かない。
  * アリと巡回する敵が、同じ1ステップで互いのマスへ入れ替わる場合も、アリが先に動く。アリが入ったマスに敵がまだいれば、戦闘になる（`RL-ENEMY-02`）。
  * 武器を持ったアリに討伐された敵は、マップからいなくなる（ゾーンは残る）。
* ステップ数は、アリの行動（向く・移動・ジャンプ・待つ・アイテムを捨てる）1回につき1ステップとする。移動関数は（回数+1）ステップ。制御ブロックの実行、条件の評価、アイテム取得、スイッチ作動、敵との戦闘ではステップは増えない。

#### (6) 上限・境界値・補足
##### 最大ステップ数（50回）の境界
| ID | 内容 |
| :--- | :--- |
| `RL-STEP-01` | 50回目の行動でゴールに着いたときは、クリア（実行回数 50）。 |
| `RL-STEP-02` | 50回行動したあと、**まだ行動するブロックが残っている**ときは、51回目の行動をしようとした時点で停止し、`STEP_LIMIT_EXCEEDED`（失敗）。このとき実行回数は 50 のままで、51回目は実行しない。 |
| `RL-STEP-03` | 50回行動して、実行するブロックがそれ以上無く、ゴールに着いていないときは、`NOT_REACHED_GOAL`。 |
| `RL-STEP-04` | 上限による停止は、テスト実行でも失敗として扱い、理由を表示する。 |

##### 最大処理回数（1000回）の境界
| ID | 内容 |
| :--- | :--- |
| `RL-LOOP-01` | 処理回数（(1) の数え方）が **1000回を超えた**時点で停止し、`LOOP_LIMIT_EXCEEDED`（失敗）。1000回ちょうどは停止しない。 |
| `RL-LOOP-02` | 中身が空の「…の間」「回くり返す」も、1周ごとに数えるため、必ず停止する。 |

##### 入れ子の深さ・ブロック数
| ID | 内容 |
| :--- | :--- |
| `RL-NEST-01` | 制御ブロック（もし・の間・回くり返す）は、**6段まで**重ねられる。7段目の制御ブロックを含むプログラムは `PROGRAM_TOO_DEEP`（400）で拒否する。6段目の制御ブロックの中には、制御ブロックでないブロック（向く・移動など）だけ置ける。 |
| `RL-NEST-02` | ブロック数は、入れ子の中も含めて**200個まで**。201個以上は `PROGRAM_TOO_LONG`（400）。 |

##### その他の補足
| ID | 内容 |
| :--- | :--- |
| `RL-OVER-01` | クリアまたは失敗が決まった時点で、残りのブロックは実行しない。敵も動かない。 |
| `RL-TEST-01` | テスト実行は、ゴールに着いてもクリアにならない。ゴール以後も、プログラムを最後まで実行する。 |

### 2.3. ステージおよびオブジェクト仕様要件

#### (1) マップ構成要素
* **道:** アリが移動可能なマス。
* **壁:** アリが移動できない障害物マス。
* **落とし穴:** 移動すると即座にゲームオーバーとなる危険マス。ジャンプで飛び越えられる。
* **ゴール:** 到達するとクリアとなるマス。
* **スイッチ:** 物資を持って乗ると物資を消費して作動し、同じ記号のドアを開くマス。通行は常に可能。
* **接敵ゾーン:** 巡回する敵が往復する範囲のマス。プレイヤーと敵が重なる可能性のある部分で、画面では色を付けて表示する。アリは通行できる。縦または横の1列に、途切れずに2マス以上並べる。各ゾーンに敵が1体付く。ゾーンは1ステージに5つまで置ける。
* **ドア:** 閉じている間は通行できず、ジャンプの着地点にもできない。対応するスイッチが作動すると開き、通常の道と同様に通行できる。
* **配置オブジェクト:** アイテム（物資・武器）、敵（動かない敵）。ステージ作成時、アイテムと動かない敵は道のマスの上にのみ置ける（接敵ゾーン、スイッチ、ドアのマスにはアイテムを置けない）。ただし、プレイ中に「アイテムを捨てる」で置いたアイテムは、アリが立てるマスならどこにでも置かれる。1つのマスに置けるアイテムは1つだけ。

スイッチとドアは**記号で対応**させる。1ステージに複数の組を置くことができ、同じ記号のスイッチやドアを複数置くこともできる（記号は5種類 a〜e / A〜E）。スイッチを置いた場合は対応するドアも必ず置く（逆も同様）。

#### (2) クリア目標の種類
* **移動タイプ:** アリを指定されたゴールまで移動させる。
* **ギミックタイプ:** マップ上の物資を取得してスイッチを作動させ、ドアを開いてゴールまで移動させる。
* **戦闘タイプ:** 武器を取得し、敵のいるマスを通って（敵を討伐して）ゴールまで移動させる。

#### (3) ステージデータの形式
ステージは外部のテキストファイル（`stage<番号>.txt`、UTF-8）で管理し、ファイルの追加・編集だけでステージを増減・変更できる。`name:`でステージ名、`description:`でステージ選択画面に出す一言説明（省略可）、`facing:`でアリの最初の向き（right / left / up / down。省略すると right）、`map:`以降でマップを指定する。マップは縦5×横9の文字で表す。

| 記号 | 意味 | 記号 | 意味 |
| :--- | :--- | :--- | :--- |
| `.` | 道 | `#` | 壁 |
| `P` | 落とし穴 | `G` | ゴール |
| `S` | スタート地点（1つだけ） | `M` | 物資（道の上） |
| `W` | 武器（道の上） | `X` | 動かない敵（道の上。画面表示は🐍） |
| `a`〜`e` | スイッチ | `A`〜`E` | ドア（`a`の作動で`A`が開く） |
| `1`〜`5` | 接敵ゾーン（同じ数字を縦か横に連続して並べる。敵は左端／上端から動き始める） | | |

```
name: 扉の向こうへ
facing: right
map:
......#..
......#..
S.M.a.A.G
......#..
......#..
```

#### (4) ステージ別仕様

### 2.4. API仕様要件
詳細な仕様は `ant-game/README.md` の「API」にある。ここには、テストの根拠になる要点を載せる。

| ID | API | 内容 |
| :--- | :--- | :--- |
| `FR-API-01` | `GET api/stages` | ステージの一覧（番号・名前・説明）を、番号の小さい順に返す。ステージファイルの誤りがあるときは `500 STAGE_DATA_ERROR`。 |
| `FR-API-02` | `GET api/stage?id=N` | マップ（5行）・開始位置・最初の向き・敵の初期位置を返す。`id` が数値でないときは `400 INVALID_STAGE_ID`、ファイルが無いときは `404 STAGE_NOT_FOUND`。 |
| `FR-API-03` | `POST api/run` | プログラムを最後まで実行し、結果（`status`、`failReason`、`stepCount`、1ステップごとの `trace`）を返す。クリアも失敗も `200`。`testRun: true` のときは、ゴールの判定をしない。 |

API のエラー応答（`FR-API-04`）: 上記の各APIが自分で返すエラーは、`{"error":"コード"}` の JSON。このほか、`/api/` 配下で起きた 400・404・405・500 は、`FR-ERR-03` のとおり JSON で返す（例: `GET api/run` は `405 METHOD_NOT_ALLOWED`）。

`POST api/run` の入力検証:

| 検査 | 条件 | エラー |
| :--- | :--- | :--- |
| Content-Type | `application/json` で始まること | `415 UNSUPPORTED_MEDIA_TYPE` |
| 本文の大きさ | 64KB（65,536文字）以下 | `413 REQUEST_TOO_LARGE` |
| JSON | 正しい形式 | `400 INVALID_JSON` |
| 最上位 | オブジェクト | `400 INVALID_REQUEST` |
| `stageId` | 1〜10000の整数 | `400 INVALID_STAGE_ID` |
| `program` | 配列 | `400 INVALID_PROGRAM` |
| `testRun` | 省略可。真偽値のみ | `400 INVALID_REQUEST` |
| ブロック | 種類・方向・条件・回数（1〜100）が許可した値 | `400 INVALID_BLOCK` |
| ブロックのID | 英数字・`-`・`_` の1〜32文字 | `400 INVALID_BLOCK_ID` |
| 入れ子 | 制御ブロックは6段まで | `400 PROGRAM_TOO_DEEP` |
| ブロック数 | 200個まで | `400 PROGRAM_TOO_LONG` |
| ステージ | ステージファイルがある | `404 STAGE_NOT_FOUND`（誤りがあれば `500 STAGE_DATA_ERROR`） |

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1. 動作環境・プラットフォーム要件
* **対応プラットフォーム:** PC用Webブラウザ
* **推奨ブラウザ:** Google Chrome
* `NFR-ENV-01` ブラウザのバージョンは特に指定しない。検証したバージョンを、テスト仕様書に記録する。
* `NFR-ENV-02` サーバー環境は、Java 21、Jakarta Servlet 6（Tomcat 10）。起動は `build\ant-game.war` を Tomcat の `webapps` に置き、`http://localhost:8080/ant-game/` を開く。
* `NFR-ENV-03` 推奨の解像度・ウィンドウの大きさは特に定めない。マップは、表示領域に合わせて1マスの大きさを変える（最小24px）。

### 3.2. 技術スタック・使用言語要件
* **フロントエンド:** HTML, CSS, JavaScript
* **バックエンド・処理エンジン:** Java（Tomcat10サーバーを使用）

### 3.3. データ管理（非保持）要件
* **データ保存機能の非対応:** 
  データベース（DB）やブラウザストレージ（LocalStorage等）を使用した永続的なデータ保存の仕組みは一切保持しない。
  ページのリロードやブラウザの閉鎖により、プレイ進行状況および作成されたプログラムはリセットされる仕様とする。
  * **例外（失敗後のやり直し用）:** 失敗から再開するときのプログラムの受け渡しにだけ、ブラウザのタブの中だけに残る一時的な保存場所（sessionStorage）を使う。タブを閉じると消え、サーバーへは送らない。LocalStorage のような、ずっと残る保存は使わない。
  * `NFR-DATA-01` sessionStorage のキー名は `ant.retryProgram`、中身は `stageId` と `program`。
* `NFR-DATA-02` ステージファイルは、UTF-8、1ファイル8KBまで、ファイル名 `stage<1〜9999>.txt`。BOM付きのファイルも読める。ステージの形式に誤りがあるときは、APIが `STAGE_DATA_ERROR`（500）を返し、原因はサーバーのログに出す。

### 3.4. 性能および安全対策（UX/パフォーマンス）要件
* **実行ハイライト表示:** 処理実行中、動的にステップを読み込み、対応するブロック要素をCSS/JavaScriptでリアルタイムに強調（ハイライト）表示する。
* **無限ループ対策:** プログラム実行時、最大ステップ数制限（50回）と最大処理回数制限（1000回）により強制停止処理を介入させ、ブラウザのフリーズを防止する。
* `NFR-PERF-01` 1ステップの再生は 420ミリ秒。50ステップで約21秒。
* `NFR-PERF-02` APIの応答時間の目標値は、特に定めない。

### 3.5. セキュリティ要件
* `NFR-SEC-01` **XSS対策:** 画面への文字の表示は `textContent` のみ。JSON出力は `< > & '` を `\uXXXX` にエスケープする。ブロックIDは英数字のみ。エラーに入力値を含めない。
* `NFR-SEC-02` **レスポンスヘッダー:** 全レスポンスに `Content-Security-Policy`（自サイトのスクリプトのみ）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Cache-Control: no-cache` を付ける（エラー応答を含む。`FR-ERR-04`）。APIは `Cache-Control: no-store`。
* `NFR-SEC-03` **入力検証:** 2.4 の検証と上限（64KB・200個・6段・回数1〜100・ID形式）。
* `NFR-SEC-04` **パストラバーサル対策:** ステージファイル名は、ステージ番号（整数）から作る。外部の文字列でファイルを指定しない。
* `NFR-SEC-05` **Tomcat側の設定:** 次の2つを、Tomcat の `conf/server.xml` に設定する（設定例と、専用のエラーページ `error.html` は、`ant-game/tomcat/` にある）。
  * Connector の `relaxedQueryChars` で、クエリの `"` `<` `>` `[` `\` `]` `^` `` ` `` `{` `|` `}` を、アプリまで通す。通すと、アプリが値を検査し、`400 INVALID_*` を JSON で返し、セキュリティヘッダーが付く。アプリは、リクエストの内容を画面に表示しない（`NFR-SEC-01`）。
  * Host の `ErrorReportValve` で、標準のエラーページ（例外の詳細・Tomcat のバージョンが出る）の代わりに `error.html` を返す（`showReport="false"`、`showServerInfo="false"`、`errorCode.0`）。
  * **制限事項:** パスに不正な文字（`%00`、`\` など）を含むリクエストや、壊れたリクエストは、アプリに届く前に Tomcat が `400` で断る。この応答は `error.html` になるが、アプリが関与できないため、**セキュリティヘッダー（`Referrer-Policy` など）は付かない**。
