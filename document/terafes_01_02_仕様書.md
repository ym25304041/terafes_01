# システム機能・画面仕様書：『アント・コマンド（仮題）』

## 1. 概要
本仕様書は、PCブラウザ（Chrome）上で動作する未経験者向けプログラミング学習ゲームの機能要件および非機能要件を定義したドキュメントである。
プレイヤーはドラッグ＆ドロップ形式でコーディングブロックを組み立て、アリ型ロボットの行動をプログラミングしてステージクリアを目指す。

---

## 2. 機能要件 (Functional Requirements)

### 2.1. 画面構成および画面遷移要件
画面遷移順序は以下の通りとする。
`TOP画面` ➔ `ステージ選択画面` ➔ `ゲームプレイ画面` ➔ `リザルト画面`

#### (1) TOP画面
* **配置要素:**
  * 画面中央上部: ゲームタイトルのテキストを表示。
  * 画面中央下部: 「ゲーム開始」ボタンを設置。
* **動作仕様:**
  * 「ゲーム開始」ボタンをクリックすると、ステージ選択画面へ遷移する。

#### (2) ステージ選択画面
* **配置要素:**
  * 画面左側（幅の1/3または1/4領域）: 簡単なゲームルール説明を掲載。
  * 画面メイン領域: 整然と並んだ四角いブロック形式のステージ選択ボタンを配置。
* **動作仕様:**
  * 選択されたステージのゲームプレイ画面へ遷移する。

#### (3) ゲームプレイ画面
* **配置要素:**
  * **ステージ描画エリア:** 画面全体が見えるサイコロ状のマス目（グリッド）で区切られた2Dマップ。
  * **コーディングエリア:** アリを操作するためのプログラムブロックをドラッグ＆ドロップで配置・組み立てる領域。
  * **操作ボタン群:**
    * 「実行」ボタン
    * 「やり直す（リセット）」ボタン
    * 「ステージ選択に戻る」ボタン
* **動作仕様:**
  * ステージ開始時にクリア目標を表示する。
  * ブロックをドラッグ＆ドロップでコーディングエリアに配置・編集できる。
  * 「実行」ボタン押下時、プログラムに従ってアリが自動行動を開始する。
  * アリが動作している間、現在実行されているブロックを強調（ハイライト）表示する。
  * 失敗時（途中でゲームオーバーになった場合）はその場で動作が停止し、画面に失敗メッセージを表示した上で「実行」直前の状態に戻る。
  * クリア条件を満たした場合、リザルト画面へ遷移する。

#### (4) リザルト画面
* **配置要素:**
  * 画面上部: クリアまでにかかったプログラムの実行回数を表示。
  * 画面下部左側: 「戻る」ボタン（ステージ選択画面へ戻る）。
  * 画面下部右側: 「次のステージ」ボタン（次のステージのゲームプレイ画面へ進む）。

### 2.2. プログラミング（コーディング）仕様要件

#### (1) 基本仕様
* **ブロック配置:** 基本動作を記述したブロックを上から順に実行順序に従ってドラッグ＆ドロップで配置する。
* **ネスト（構造化）仕様:** 特殊処理ブロックは内部に他のブロックや枠を配置可能な「覆う枠」として機能し、条件と動作を設定できる。
* **最大ステップ数制限:** 1つのプログラムで実行できる処理（アリの行動＝移動・ジャンプ・待つ）の上限は最大100回までとし、超えた場合は安全のため停止する。
* **最大処理回数制限:** アリが行動しないまま回り続けるプログラム（中身が空のくり返しなど）を止めるため、ブロックの実行・条件の評価・くり返しの回数の合計が1000回を超えた場合も停止する。
* **時間（ターン）の考え方:** アリが1回行動する（移動・ジャンプ・待つ）ごとに時間が1ステップ進む。壁にぶつかって動けなかった場合やジャンプに失敗した場合も1ステップ進む。1ステップの順番は「アリが先に行動 → そのあと敵が動く」とする。条件の評価だけでは時間は進まない。
* **入れ子の制限:** 制御ブロックの入れ子は6段まで、ブロックの合計数は200個までとする。

#### (2) 基本動作ブロック一覧
| ブロック名 | 動作仕様 |
| :--- | :--- |
| **移動** | グリッド上の絶対位置（上・下・左・右）へ1マス移動する。※壁・マップ外・閉じたドアには移動できず、その場にとどまる（1ステップとして数える）。敵のいるマスへ移動した場合は戦闘になる（2.2.(5)を参照）。 |
| **待つ** | その場で1ステップ待つ。アリは動かないが時間は進み、敵は動く。 |
| **ジャンプする** | 前方1マスが落とし穴のときだけ成功し、その1つ先のマスへ着地する。前方が落とし穴でない場合、または着地点が壁・閉じたドア・マップ外の場合は失敗し、その場にとどまる（1ステップとして数える）。着地点が落とし穴の場合は落下して失敗となる。 |

※アイテムの取得・スイッチの作動・敵との戦闘は、ブロックを使わず**自動で**行われる（2.2.(5)を参照）。「物を拾う」「物を置く」「攻撃する」ブロックは存在しない。

#### (3) 特殊処理（制御）ブロック一覧
制御ブロックは、内部に他のブロックを入れられる枠として機能する。制御ブロックの実行自体では、時間（ステップ）は進まない。
* `もし(条件)なら(動作)する`（「そうでなければ(動作)する」の枠も持つ。省略した場合は何もしない）
* `(条件)の間(動作)し続ける`（毎回、先に条件を調べる。条件が成り立たなくなったら抜ける）
* `(数値)回実行する`（回数は1〜100）

条件には、「〜でない」を指定して、成り立つ・成り立たないを反転できる（例: 目の前に壁がない間、進み続ける）。

#### (4) 条件式一覧
* `目の前に壁があったら`
* `目の前に敵が居たら`
* `目の前に落とし穴があったら`
* `目の前に敵が来るなら`

「目の前」とは、アリが向いている方向（最後に移動・ジャンプを試みた方向。最初は右向き）の1マス先を指す。壁にぶつかって動けなかった場合も、その方向を向く。
* `目の前に壁があったら`: 目の前が壁、またはマップの外（マップの端は壁として扱う）。閉じたドアは壁として扱わない。
* `目の前に敵が居たら`: 目の前のマスに、今、敵がいる（動かない敵・巡回する敵のどちらも）。
* `目の前に敵が来るなら`: 敵が目の前のマスに、今いる、または次のステップで入ってくる。「安全に進めるか」の確認に使う。

※「進んだ位置に物が落ちていたら」「進んだ位置に物を置ける場所があったら」は、アイテムの取得・消費を自動化したため廃止した。

#### (5) アイテム・スイッチ・ドアの自動処理
アリがマスに着いた（移動またはジャンプの着地）時点で、次の処理が自動的に行われる。実行順序は「落とし穴の判定 → アイテム取得 → 敵との戦闘 → スイッチ作動 → ゴール判定」とする。

* **アイテム取得:**
  * アイテムのあるマスにアリが着くと、自動で取得する。取得したアイテムはそのマスからなくなる。
  * アイテムは「物資」と「武器」の2種類で、アリは**それぞれ1つずつ**（別々のスロットに）持てる。
  * すでに同じ種類を持っている場合は取得せず、アイテムはそのマスに残る。
* **スイッチ作動:**
  * スイッチのマスにアリが着いたとき、物資を持っていれば、物資を1つ消費してスイッチが作動し、**同じ記号のドアがすべて開く**。
  * 物資を持っていない場合は何も起きない（スイッチのマスは通行できる）。後で物資を取得してから戻れば作動できる。
  * 作動したスイッチは再度乗っても物資を消費しない。ドアは一度開くと開いたままとなる。
* **武器:** 敵との戦闘判定に用いる。「持っているかどうか」のみを管理し、種類や強さはない。
* **敵との戦闘:**
  * 敵は「動かない敵」と「巡回する敵」の2種類で、どちらも道のマス（巡回する敵は接敵ゾーン）の上にいる。
  * アリと敵が同じマスになった時点で、自動的に戦闘となる。次の2つの場合がある。
    * アリが敵のいるマスに着いた（移動またはジャンプの着地。アリの行動中）
    * 巡回する敵が動いて、アリのいるマスに入ってきた（敵の行動中。アリがその場で待っていても起きる）
  * **武器を持っている場合:** 敵を討伐し、そのマスに進める。討伐した敵はマップからいなくなる。武器は消費されないため、同じ武器で何体でも討伐できる。
  * **武器を持っていない場合:** 敗北し、ゲームオーバーとなる。物資だけを持っていても討伐はできない。
  * 実行順序は「落とし穴の判定 → アイテム取得 → 敵との戦闘 → スイッチ作動 → ゴール判定」とする。
* **巡回する敵（接敵ゾーン）:**
  * 敵は、決められた範囲（接敵ゾーン）を**縦1列、または横1列の直線上だけ**で往復する。複雑な動きはしない。
  * アリの行動のあと、敵は1ステップにつき1マス進む。範囲の端に着いたら、すぐに折り返す（端で止まらない）。
  * 敵は、ゾーンの左端（縦のゾーンは上端）から、反対側の端へ向かって動き始める。
  * アリが先に行動し、そのあとで敵が動く。アリの行動でクリア・失敗が決まった場合、敵は動かない。
  * 武器を持ったアリに討伐された敵は、マップからいなくなる（ゾーンは残る）。
* ステップ数は、アイテム取得・スイッチ作動では増えない（ブロックの実行1回につき1ステップ）。

### 2.3. ステージおよびオブジェクト仕様要件

#### (1) マップ構成要素
* **道:** アリが移動可能なマス。
* **壁:** アリが移動できない障害物マス。
* **落とし穴:** 移動すると即座にゲームオーバーとなる危険マス。ジャンプで飛び越えられる。
* **ゴール:** 到達するとクリアとなるマス。
* **スイッチ:** 物資を持って乗ると物資を消費して作動し、同じ記号のドアを開くマス。通行は常に可能。
* **接敵ゾーン:** 巡回する敵が往復する範囲のマス。プレイヤーと敵が重なる可能性のある部分で、画面では色を付けて表示する。アリは通行できる。縦または横の1列に、途切れずに2マス以上並べる。各ゾーンに敵が1体付く。ゾーンは1ステージに5つまで置ける。
* **ドア:** 閉じている間は通行できず、ジャンプの着地点にもできない。対応するスイッチが作動すると開き、通常の道と同様に通行できる。
* **配置オブジェクト:** アイテム（物資・武器）、敵（動かない敵）。アイテムと動かない敵は道のマスの上にのみ置ける。接敵ゾーン、スイッチ、ドアのマスにはアイテムを置けない。

スイッチとドアは**記号で対応**させる。1ステージに複数の組を置くことができ、同じ記号のスイッチやドアを複数置くこともできる（記号は5種類 a〜e / A〜E）。スイッチを置いた場合は対応するドアも必ず置く（逆も同様）。

#### (2) クリア目標の種類
* **移動タイプ:** アリを指定されたゴールまで移動させる。
* **ギミックタイプ:** マップ上の物資を取得してスイッチを作動させ、ドアを開いてゴールまで移動させる。
* **戦闘タイプ:** 武器を取得し、敵のいるマスを通って（敵を討伐して）ゴールまで移動させる。

#### (3) ステージデータの形式
ステージは外部のテキストファイル（`stage<番号>.txt`、UTF-8）で管理し、ファイルの追加・編集だけでステージを増減・変更できる。マップは縦5×横9の文字で表す。

| 記号 | 意味 | 記号 | 意味 |
| :--- | :--- | :--- | :--- |
| `.` | 道 | `#` | 壁 |
| `P` | 落とし穴 | `G` | ゴール |
| `S` | スタート地点（1つだけ） | `M` | 物資（道の上） |
| `W` | 武器（道の上） | `X` | 動かない敵（道の上。画面表示は🐍） |
| `a`〜`e` | スイッチ | `A`〜`E` | ドア（`a`の作動で`A`が開く） |
| `1`〜`5` | 接敵ゾーン（同じ数字を縦か横に連続して並べる。敵は左端／上端から動き始める） | | |

```
name: 扉の向こうへ
map:
......#..
......#..
S.M.a.A.G
......#..
......#..
```

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1. 動作環境・プラットフォーム要件
* **対応プラットフォーム:** PC用Webブラウザ
* **推奨ブラウザ:** Google Chrome

### 3.2. 技術スタック・使用言語要件
* **フロントエンド:** HTML, CSS, JavaScript
* **バックエンド・処理エンジン:** Java（Tomcat10サーバーを使用）

### 3.3. データ管理（非保持）要件
* **データ保存機能の非対応:** 
  データベース（DB）やブラウザストレージ（LocalStorage等）を使用した永続的なデータ保存の仕組みは一切保持しない。
  ページのリロードやブラウザの閉鎖により、プレイ進行状況および作成されたプログラムはリセットされる仕様とする。

### 3.4. 性能および安全対策（UX/パフォーマンス）要件
* **実行ハイライト表示:** 処理実行中、動的にステップを読み込み、対応するブロック要素をCSS/JavaScriptでリアルタイムに強調（ハイライト）表示する。
* **無限ループ対策:** プログラム実行時、最大ステップ数制限（100回）により強制停止処理を介入させ、ブラウザのフリーズを防止する。
